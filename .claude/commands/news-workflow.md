# 뉴스 수집기 기능 개발 워크플로우

새 기능을 개발할 때 사용하는 명령어입니다.
브랜치 이름: $ARGUMENTS

아래 과정을 순서대로 실행해줘.

## 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 상태를 확인해.
- 현재 브랜치가 main이 아니라면 경고를 주고, main으로 이동할지 사용자에게 물어봐. 사용자가 동의하면 이동하고, 거절하면 여기서 중단해.
- 커밋되지 않은 변경 사항이 있으면 함께 알려줘.

## 2. 새 브랜치 생성
- $ARGUMENTS로 받은 이름으로 새 브랜치를 만들어줘 (`git checkout -b <이름>`).
- 브랜치 이름을 입력받지 못했다면, 어떤 기능을 개발할 것인지 사용자에게 물어봐. 답변을 바탕으로 영어 소문자-하이픈 형식(예: `category-filter`)의 브랜치 이름을 제안하고, 사용자가 확인하면 그 이름으로 만들어줘.

## 3. 개발 시작 안내
- 브랜치 생성이 끝나면 '이제 개발을 시작하세요!'라고 안내해.
- `CLAUDE.md`를 참고해서 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 알려줘.
  - 기술 스택, 핵심 동작 규칙, 데이터 모델, 구현 단계 등
  - 기능 요구사항은 `PRD.md`, UI 작업은 `ui.md`를 먼저 읽어야 한다는 점
  - Next.js 코드를 쓰기 전에 `node_modules/next/dist/docs/`의 관련 가이드를 확인해야 한다는 점

## 4. 완료 처리
- 사용자가 '완료' 또는 'done'이라고 입력하면 다음을 실행해.
  1. `git status`로 변경된 파일 목록을 보여줘.
  2. **(필수) `convention-checker` 서브에이전트를 Agent 도구로 호출해 코드 검토를 받아.** 린트·타입 검사는 이 검토를 대신하지 못한다. 지적 사항이 있으면 수정한 뒤 사용자에게 결과를 요약해서 알려줘. 이 단계를 마치기 전에는 커밋 메시지 제안으로 넘어가지 마.
  3. 변경 내용(`git diff`)을 바탕으로 커밋 메시지를 자동으로 제안해. 기존 커밋 로그(`git log`)의 스타일(한국어, 한 줄 요약)을 따라.
  4. 사용자가 확인하면 변경 파일을 스테이징하고 커밋해.
  5. 커밋 후 main으로 이동해서 작업 브랜치를 병합해 (`git checkout main` → `git merge <브랜치>`).
- 사용자가 확인하기 전에는 커밋이나 병합을 하지 마. 병합 중 충돌이 나면 멈추고 사용자에게 알려줘.

## 5. 작업 요약
- 병합이 끝나면 작업 내용을 요약해서 보여줘.
  - 브랜치 이름, 커밋 메시지, 변경된 파일 목록
  - 구현한 기능의 핵심 내용
